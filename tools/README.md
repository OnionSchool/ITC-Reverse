# 离线抓包

本流程用于在授权的隔离测试环境中记录旧 ITC 系统的控制与媒体流量，为兼容实现提供证据。`ITCCapture.exe` 只读取网卡报文，不发送报文、不启动旧服务、不改写旧安装目录或 MDB。测试网没有公网是预期的安全条件。

## 需要的文件和设备

- 测试机：Windows 7 SP1 或更高版本，具有连接隔离测试网络的有线网卡和本机管理员权限。
- 抓包工具：离线 Npcap 安装包，以及本项目构建产物中的 `ITCCapture.exe`。
- 测试设备：旧服务端、旧管理端、至少一台已获授权的旧终端。
- 网络：独立交换机，或仅主机的隔离虚拟网络；不要连接校园网、互联网或 NAT 网络。
- 转运介质：U 盘，用于把 Npcap、`ITCCapture.exe` 带入，以及将 PCAP 带至分析机。

无需安装 Wireshark、PowerShell、Python 或任何网络服务。Npcap 是唯一需要安装的组件；`ITCCapture.exe` 运行时从 Npcap 加载 `wpcap.dll`。

## 1. 建立隔离网络

1. 断开测试机、旧服务端、管理端及终端的 Wi-Fi、VPN、蓝牙网络、移动网络、第二张网卡和所有 USB 网络共享。
2. 将旧服务端、旧管理端、终端和抓包机连接至一台不连接外网的独立交换机。抓包机可就是旧服务端或管理端所在的测试机；若抓包机是另一台设备，需使用交换机端口镜像或把它置于透明桥接路径，否则它通常无法看到其他两台设备之间的单播 TCP 流量。
3. 为测试网卡设定静态地址。示例：服务端 `10.77.0.10/24`、管理端 `10.77.0.20/24`、终端 `10.77.0.30/24`、抓包机 `10.77.0.40/24`。
4. 所有设备的默认网关和 DNS 服务器均留空。不要启用 Internet Connection Sharing、网络桥接到外网或 NAT。
5. 用 `ipconfig /all` 检查：测试网卡仅有上述静态 IPv4 地址，没有默认网关和 DNS；其他网络适配器显示“媒体已断开连接”或已禁用。
6. 在 Windows 防火墙中仅保留测试网卡所需的本地通信规则。不要为本次抓包关闭整个系统防火墙。

## 2. 安装并确认 Npcap

1. 在可联网的另一台电脑下载适用于测试机架构的 Npcap 离线安装程序，用 U 盘复制到测试机。
2. 以管理员身份安装 Npcap，只安装抓包驱动即可；不要安装 Wireshark。
3. 将 CI 构建产物 `ITCCapture.exe`、`capture-itc.cmd` 和 `list-capture-interfaces.cmd` 放入同一目录，例如 `C:\ITCCapture`。
4. 以管理员身份打开 `cmd.exe`，切换到该目录：

```bat
cd /d C:\ITCCapture
ITCCapture.exe --list
```

若显示“未检测到 Npcap”，确认 Npcap 已安装完成后重启测试机，再重新执行。不要从不可信来源下载 `wpcap.dll`；它应由 Npcap 安装。

## 3. 确定网卡编号

运行下列任一命令：

```bat
ITCCapture.exe --list
list-capture-interfaces.cmd
```

输出示例：

```text
1    \Device\NPF_{...}    Realtek PCIe GbE Family Controller
2    \Device\NPF_{...}    Wi-Fi
```

第一列的 `1`、`2` 是 Npcap 的接口编号，不是 IP 地址。选择描述为接入隔离测试网的有线网卡的编号。上例中应选择 `1`；不要选择 Wi-Fi、VPN、蓝牙或虚拟网卡。

## 4. 开始只读抓包

先创建输出目录并启动抓包：

```bat
mkdir captures
ITCCapture.exe --interface 1 --output captures\itc-001.pcap
```

也可使用包装脚本：

```bat
capture-itc.cmd 1 captures\itc-001.pcap
```

将 `1` 改为上一步选定的接口编号。工具会显示已启用的过滤器，然后持续运行；它只保留：

- TCP `8000`：已确认的控制端口。
- TCP `15001`：已确认的数据端口。
- 目标为 `225.101.1.0/24` 的 UDP：已确认的组播地址池。

工具不会向网络发出探测、登录、ARP、组播加入或任何其他应用层请求。按 `Ctrl+C` 停止；脚本随后会用 Windows 自带 `certutil` 为 PCAP 创建同名 `.sha256` 文件。

## 5. 在旧管理端执行最小操作序列

抓包开始后，仅在旧管理端以人工方式执行一次可重复的最小操作序列，并记录每一步的本地时间：

1. 启动旧服务端及旧管理端，等待界面和服务稳定。
2. 登录旧管理端。
3. 新建一个测试会话，名称使用固定且不含真实信息的文本，例如 `CAPTURE-001`。
4. 只加入一台授权测试终端。
5. 选择一个可公开使用的短测试音频，或只创建会话但不播放，以区分控制面与媒体面。
6. 开始播放，保持 15 至 30 秒。
7. 修改一次已知状态，例如音量；再停止播放并删除测试会话。
8. 关闭旧管理端，等待 10 至 20 秒后按抓包窗口的 `Ctrl+C`。

不要在此次采集中操作真实课堂终端、真实广播任务、对讲、SOS、录音或含个人信息的媒体。若需要单独确认 TCP `15001` 或组播，可在第二个独立 PCAP 中重复第 3 至第 7 步，避免混淆。

## 6. 保存、校验与脱敏

1. 保留 `captures\itc-001.pcap` 原件及 `captures\itc-001.pcap.sha256`，不要在原件上修改。
2. 将文件复制到 U 盘后，在目标机再次运行：

```bat
certutil -hashfile captures\itc-001.pcap SHA256
```

将输出与 `.sha256` 内的哈希比较，确认副本完整。
3. 复制一份 PCAP 用于分析，原始文件单独只读保存。
4. 若 PCAP 含真实用户名、密码、校园 IP、终端名称、录音或媒体内容，先在副本中脱敏；不要上传 MDB、配置文件、明文凭据或未脱敏的媒体。

## 7. 离线分析与交付

可将副本带到另一台分析机，用 Wireshark 或其他离线分析器查看。常用显示过滤器：

```text
tcp.port == 8000
tcp.port == 15001
ip.dst >= 225.101.1.1 && ip.dst <= 225.101.1.253
```

交付时请同时附上：PCAP 副本、SHA-256、测试网段说明、管理端/服务端/终端的脱敏 IP、接口描述和编号、操作步骤与时间顺序、旧系统版本号，以及该轮是否实际播放音频。这样可重建登录、会话命令、15001 握手和组播媒体格式，而无需接触生产网络。

## 单机抓包：仅旧服务端电脑

若只有旧服务端电脑，也可以在该电脑本机抓取旧服务进程的入站和出站流量。此方案能记录本机管理界面到服务的控制连接、终端连接服务端的 TCP 流量，以及服务端发出的组播；无法凭空产生不存在的终端或外部管理端流量。

### 单机前提

1. 在旧服务端电脑上安装 Npcap，并将 `ITCCapture.exe`、`capture-itc.cmd`、`list-capture-interfaces.cmd` 放到 `C:\ITCCapture`。
2. 断开该电脑的 Wi-Fi、VPN、蓝牙网络、移动网络和不属于测试的网卡；保留旧广播系统实际使用的有线网卡。没有公网和默认网关是正常且推荐的状态。
3. 不修改原安装目录、MDB 或原服务配置；抓包工具输出到 `C:\ITCCapture\captures`，不要写入旧系统目录。
4. 若旧管理端程序安装在同一台电脑，可用它执行下文操作；它与服务端之间即使使用回环地址，也会出现在 Npcap 的回环接口或实际网卡接口上，具体取决于旧程序连接的地址。

### 识别应抓接口

以管理员身份打开 `cmd.exe`：

```bat
cd /d C:\ITCCapture
ITCCapture.exe --list
ipconfig /all
```

先选择连接旧终端的有线网卡。若旧服务配置或管理界面显示连接地址是 `127.0.0.1`，还需记录 Npcap 输出中描述为 `Npcap Loopback Adapter` 的接口编号；它用于抓本机回环控制流量。建议分两轮抓取：第一轮抓有线网卡，第二轮抓回环接口，避免接口选择不确定时遗漏控制连接。

### 抓取有线终端与组播流量

在第一个管理员 `cmd.exe` 窗口执行，按实际编号替换 `1`：

```bat
mkdir captures
ITCCapture.exe --interface 1 --output captures\server-lan.pcap
```

保持窗口打开。在同机旧管理端执行一次最小操作序列：登录、创建名为 `CAPTURE-LOCAL-001` 的测试会话、加入授权终端、开始播放 15 至 30 秒、调整一次音量、停止并删除会话。完成后回到抓包窗口按 `Ctrl+C`。

此 PCAP 的预期内容是服务端与终端间的 TCP `8000`/`15001` 流量，以及服务端发往 `225.101.1.1` 至 `225.101.1.253` 的 UDP 组播。若当前没有连接的授权终端，文件可能只包含服务端自身广播或没有匹配报文；这是有效结果，应如实记录。

### 单独抓取本机回环控制流量

如果旧管理端和服务端都在本机、或配置中服务地址为 `127.0.0.1`，停止上一轮后执行：

```bat
ITCCapture.exe --interface 2 --output captures\server-loopback.pcap
```

将 `2` 替换为 `Npcap Loopback Adapter` 的编号。重复同一最小操作序列，再按 `Ctrl+C`。此文件优先用于恢复登录、`session` 命令、响应文本、连接建立与心跳；它通常不会包含发往物理终端的媒体数据。

### 校验并记录结果

`capture-itc.cmd` 会自动生成 SHA-256；直接使用 `ITCCapture.exe` 时，停止后手动生成：

```bat
certutil -hashfile captures\server-lan.pcap SHA256
certutil -hashfile captures\server-loopback.pcap SHA256
```

保存每轮的接口编号与描述、IP 地址、开始/结束时间、是否有终端在线、是否实际播放、以及 PCAP 和 SHA-256。保留原件，复制副本再脱敏分析。不要为了制造流量而连接生产终端、修改旧数据库或向 `8000`/`15001` 手工发送猜测协议。

## 故障排查

- `未检测到 Npcap`：确认已安装 Npcap，重启测试机，并从管理员 `cmd.exe` 运行工具。
- `接口编号无效`：重新执行 `ITCCapture.exe --list`；编号会随网卡、VPN 或虚拟机适配器变化。
- PCAP 为空：确认选中有线测试网卡；若抓包机是独立第三台设备，检查交换机端口镜像或透明桥接。普通交换机端口通常看不到其他设备之间的单播 TCP。
- 只有组播没有 TCP：确认抓包点能看到服务端与管理端之间的流量；端口镜像应覆盖两者所在端口。
- 无法停止：在抓包窗口按 `Ctrl+C`；不要直接断电或结束 Npcap 服务。
